# 깊어짐(③) 설계 v0.1 — 같은 고민이 나아지지 않고 깊어질 때 도움받을 곳을 안내하는 기준

작성 2026-10-26 · 근거: 전문위원 검수 묶음 v0.7 `1-3 깊어짐 기준`(상담사님 검수 반영 v3, 대표님 확정), 엔진 `lib/interp/vendor/rootState.mjs`(`onTheoryTurn`), 대표님 결정(2026-10-26: **신호 판별은 AI가 하지 않고 단어·문장 기준의 판별식으로 한다** — AI가 하면 심리상담 치료 대상으로 오인해 모든 내용을 전문의로 넘길 위험이 큼).
상태: **설계안**. 5장의 결정에 답이 나오면 구현한다.

## 1. 하려는 일

> 같은 고민(갈래=뿌리)을 여러 번 다뤘는데 나아지지 않고 **더 깊어지는 신호**가 쌓이면, **전문의·상담 기관 정보를 한 번 부드럽게 안내**하고 대화는 계속한다. **휴먼 웰니스 세션은 권하지 않는다**(일상 고민 서비스이고 병증이 의심되는 경우는 외부 전문 도움이 맞다 — 상담사님).

역할 층위(docs/제품_역할_층위.md)로 보면 **층위 6로 넘어가는 문턱을 사람이 아니라 기준표가 정하는 장치**다. 쏘웰라(층위 1~4)가 병리 판단을 하지 않으면서도, 깊어지는 사람이 계속 일상 대화에만 머물지 않게 하는 안전망.

## 2. 기준표 요약 (CSO v3, 이미 확정)

| 항목 | 내용 |
|---|---|
| 세는 단위 | 같은 뿌리를 다룬 사용자 턴(이론 탐색 턴 + 같은 주제 일반 대화 턴), **대화를 넘어 누적** |
| 확인 시작 | 그 뿌리를 다룬 지 **7~8턴째부터 매 턴** |
| 넘김 조건 | 깊어짐 신호(E-1·E-2·E-4·E-6) **2개 이상** + **나아지는 신호 없음** |
| 나아지는 신호 | "조금 나아졌어요", "해 봤어요" 같은 말이 **하나라도** 나오면 턴 수를 처음부터 다시 셈 |
| 넘길 때 | 도움받을 곳(전문의·상담 기관) 정보를 **한 번**, 대화는 계속, 휴먼 세션은 권하지 않음 |
| 이후 | 위기 이력에는 남기지 않고 뿌리의 **주의 표시(caution_hold)** — 표시 동안 그 뿌리 관련 "불편 머무르기" 실천만 제외, 안내 유지. **나아짐 신호가 나오면 해제**(기간으로 풀지 않음) |
| ②가 먼저 | 위기·안전 신호(②)는 턴 수와 상관없이 언제나 먼저 |
| 먼저 묻기(③-9) | 깊어짐으로 보이는 말도 **단어만으로 판단하지 않고** "왜 그렇게 느끼는지/무슨 일이 있었는지"를 먼저 묻고, 답을 본 뒤에 센다 |
| 신호 E-1 | 더 힘들어졌다고 **본인이 분명히** 말함("전보다 훨씬 힘들어요") — 단어 하나 변화는 안 셈 |
| 신호 E-2 | 기간이 늘어남("요즘" → "몇 달째", 2주 이상) |
| 신호 E-4 | **이유를 물은 뒤에도** 절망·무가치감이 이어짐("해 봤자 소용없어요") |
| 신호 E-6 | 운동을 못 하면 불안이 크게 커짐 + 상쇄 운동 시간·횟수 증가 |
| 뺀 신호 | E-3 범위가 넓어짐, E-5 실천을 계속 못 함(기록만, 실천 추천을 더 작게 하는 데만) |

## 3. 설계

### 3-1. 판별은 단어·문장 규칙으로만 (AI 금지)

`lib/safety/deepening.ts`(순수 함수, 테스트 가능)에 패턴 표를 둔다. AI 호출 없음.

| 신호 | 판별식(초안) | 비고 |
|---|---|---|
| E-1 | **과거와 비교하는 말 + 힘듦·악화 말** 둘 다: (전보다·예전보다·지난번보다·갈수록·점점·요즘 들어 더) + (힘들·심해·나빠·괴로·버거) | "조금→너무" 같은 정도 단어만 바뀐 경우는 안 셈 |
| E-2 | 기간 표현: 몇 달째·수개월·[2-9]달째·반년·한 달 넘·[2-9]주째·몇 주째·오래전부터 + 힘듦 맥락 | 2주 이상은 즉시 기준이 아니라 이 신호로만 셈 |
| E-4 | 절망·무가치 표현: 해 봤자 소용없·어차피 안 돼·저는 원래 안 돼·뭘 해도 안 돼·희망이 없·아무 의미 없 | **직전 쏘웰라 답변이 이유를 물었을 때만**, 그 답에도 같은 표현이 남아 있으면 셈 |
| E-6 | 운동을 못 하면 불안(운동·러닝 + 못 하면/안 하면 + 불안·초조) **그리고** 운동 시간·횟수 늘림(더 오래·시간을 늘·두 번씩) | 먹는 양 이야기만으로는 안 셈(굶기 며칠째는 SAFE-018이 바로 처리) |
| 나아짐 | 조금 나아졌·좀 나아졌·나아지고 있·한결 편해·해 봤는데 괜찮·해봤더니·도움이 됐 | 하나라도 있으면 리셋 |
| 일상 이유(셈에서 제외) | 일 때문에·야근·시험·마감·이사·감기·몸살·바빠서·출장·잠을 못 자는 이유가 분명한 말 | "먼저 묻기" 뒤 답에 이게 있으면 그 신호는 취소 |

패턴 목록은 초안이며 실제 대화 로그를 보며 넓힌다. **놓치는 쪽(안내를 덜 하는 쪽)으로 틀릴 수 있다**는 점은 기준표가 "단어만으로 판단하지 않는다"고 한 취지와 같다 — 대신 ②(위기 신호)는 이 규칙과 별개로 항상 먼저 동작한다.

### 3-2. "먼저 묻기"를 상태 저장 없이 구현

신호 후보가 나온 **다음 쏘웰라 답변**에 "그렇게 느끼신 이유(무슨 일이 있었는지)를 한 번 물어보는" 지침을 준다(`safetyGuidance`). 그다음 사용자 메시지에서:
1. 이전 사용자 메시지에서 신호 후보가 있었고,
2. 직전 쏘웰라 답변이 이유를 물었고(문구 패턴: "왜 그렇게", "무슨 일이", "어떤 일이", "이유가"),
3. 이번 답에 **일상 이유**가 없으면 → 그 신호를 **확정**으로 센다. E-4는 추가로 이번 답에도 같은 절망 표현이 남아 있어야 한다.

(대화 기록만으로 계산되므로 "후보" 상태를 따로 저장하지 않는다.)

### 3-3. 어디에 무엇을 저장하나

엔진의 표 `sw_user_root_state`(사용자×뿌리: `turns_total`, `turns_since_improve`, `escalate_seen`, `escalated_at`, `caution_hold`)가 이미 있다. 앱은 지금 이 표에 쓰지 않으므로 새로 연결한다.
- 읽기: 대화가 진행되는 동안 해당 뿌리의 행.
- 쓰기: 답변을 보낸 뒤 뒤에서 도는 해석 단계(`runInterpretation`, `after()`)에서 `onTheoryTurn`을 호출하고 `toRow`로 저장 → 결과는 **다음 턴부터** 반영(지연 0, 지금의 가설 말하기와 같은 방식).
- **새 SQL 불필요**(표 존재, service_role 권한 확인 필요 — 구현 첫 단계에서 확인).
- 사용자 삭제 시 `sw_purge_user`가 지우는지 확인(없으면 보강).

### 3-4. 어느 뿌리의 턴인지

세는 단위는 "그 뿌리를 다룬 턴"이다. 현재 뿌리는 해석 단계의 발화 분류(`classifyUtterance`, **AI 사용**)가 정한 1순위 뿌리와, 가설 말하기·선택 카드가 가리킨 뿌리에서 나온다. 즉 **"어느 뿌리인지"는 기존 AI 해석을 그대로 쓰고, "깊어졌는지"의 판단은 AI가 하지 않는다.** 이 구분이 대표님 결정(신호 판별 AI 금지)과 맞는지 5장 Q1에서 확인한다.

### 3-5. 넘길 때 쏘웰라가 하는 일

넘김 결정이 난 다음 턴, 답변 지침 블록 하나 + (한 번만):
- 지금 마음을 알아주는 말 → "이야기해 주셔서 고마워요"류 한 문장.
- **도움받을 곳 안내**(제안형, SAFE-009 문구 기준): 정신건강의학과·지역 정신건강복지센터·상담 기관을 한 번 안내. 번호는 이미 승인된 109·1577-0199 중 해당할 때만(위기 신호가 아니면 번호 없이 기관 종류만 — 5장 Q2).
- 대화는 계속한다(대화를 끊지 않음). **휴먼 웰니스 세션은 권하지 않는다.**
- 같은 넘김에서 반복하지 않는다: `escalated_at` 이후 나아짐 신호가 나오기 전에는 안내를 되풀이하지 않고, 나아짐 신호로 리셋된 뒤 다시 쌓여 넘어가면 다시 한 번.
- `caution_hold` 동안: 그 뿌리의 "불편 머무르기"(노출) 실천은 추천에서 뺀다(`excludeExposureForRoot` — 실천 검색에 연결, 지금은 미연결).

### 3-6. 운영 확인(대표님이 정한 (나) 범위와 연결)

넘김이 일어난 대화는 세션 안전 표시를 `elevated`로 남겨 운영 검토 대상으로 한다(약관 예고 4항의 "안전 확인이 필요하다고 표시된 대화"). 관리자 화면(4단계)이 만들어질 때 `caution_hold`가 켜진 사용자·뿌리 목록을 함께 보여 준다. ※ ③은 위기 이력에는 남기지 않는다(CSO ③-8).

### 3-7. 테스트 계획

- 단위(`deepening.test.ts`): 신호별 포함/제외 예시(CSO 시트 예시 그대로), 먼저 묻기 흐름(후보→질문→일상 이유 있음/없음), 나아짐 리셋, 7~8턴 시작·2신호 조건, 같은 넘김 되풀이 금지.
- 실제 경로(e2e): 임시 계정으로 같은 뿌리를 8턴 이상 이어 가며 신호를 넣어 도움받을 곳 안내가 한 번만 나오는지, 휴먼 세션 언급이 없는지, 나아짐 신호 뒤 리셋되는지.
- 안전 평가(35건)는 한 건도 깨지면 안 됨. 위기·폭력 고정 응답과 SAFE-018~021 지침이 ③보다 항상 먼저.

## 4. 대화 속도와의 관계 (함께 정할 것)

층위 구조(1번째 후보 질문 → 2번째 층위 4 가설 → 3번째부터 해결책)와 ③은 별개 장치다. 다만 "해결책을 몇 번째 답변부터 낼지"는 한 번에 정하는 편이 좋다 — 6장 참고.

## 5. 결정할 것

| Q | 내용 | 권장 |

## 6. 해결책을 몇 번째 답변부터 내나 (층위 구조 속도) — **결정·반영 완료(2026-10-26): 4번째부터**

대표님 의견: **4번째 답변부터 해결책**. 개발 의견: **적당합니다.** 이유 — 층위가 4개라 한 칸씩 내려가면 1번째(겉 이유→후보 질문) → 2번째(고른 것에서 한 칸 더) → 3번째(층위 4 가설을 사용자와 맞춰 봄) → 4번째(맞춰 본 성향에 맞춘 해결책)가 자연스럽고, 지금처럼 3번째에 제안하면 사용자가 층위 4를 확인해 주기 전에 해결책이 나가서 "이런 마음일 수도 있다"가 해결책에 반영되지 않는다. 대신 지켜야 할 것:
- 1~3번째에도 **빈손으로 질문만 하지 않는다**: 매 답변에 한두 문장의 작은 도움(공감 + 짧은 관점)을 함께 준다.
- 사용자가 먼저 "그래서 어떻게 하면 돼요?"라고 묻거나 이미 깊은 마음까지 말했으면 **앞당겨** 해결책을 낸다.
- 기존 2026-09-24 결정("3번째부터 무조건 실질적")을 이 결정이 대체한다 — 반영하면 CLAUDE.md와 `prompt.ts`의 2·3번째 지침 문구를 함께 바꾼다.
